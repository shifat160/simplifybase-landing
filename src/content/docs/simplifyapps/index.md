SimplifyApps is in design. This page exists so the documentation URL is stable
from day one — bookmark it and it will fill in rather than move.

## What it will cover

- **Data sources** — connecting a database, a sheet, or another SimplifyBase
  product, and what read/write access each one needs.
- **Forms** — conditional fields, calculated values, and validation that runs on
  the server as well as in the browser.
- **Approval chains** — routing a submission to the right people, reminders, and
  the record of who approved what.
- **Dashboards** — read-only views for people who need the numbers but should
  not have admin access.
- **Permissions** — roles defined by what someone does rather than by which
  table they need.
- **The escape hatch** — writing real logic when assembly is not enough.

## Shaping it

We are trying to find the line where low-code stops helping. If you have built
and then abandoned an internal tool, the reason it was abandoned is the most
useful thing you could tell us.
